## What was fixed

### Bug 1 — Returned items not disappearing when marked as "Kept"
Items on `#/returned` now re-render after saving edits in the Edit
modal. The page was never refreshed because `saveEditBtn` only called
`renderClosetView` (for `#/closet`) — added the matching
`renderReturnedView` call for `#/returned`.

### Bug 2 — Photo delete + replace broken
Deleting the cover photo in the Edit modal now actually clears it on
the server. Previously `db-r4.js` sent nothing when `photo = null`;
server kept the old file. Now `_itemToBody` explicitly sends
`cover_photo_path: null`, which triggers server-side deletion.
Same fix applies to `thumb_path`.

### Bug 3 — Multiple photos silently dropped
The `photos` extras array was completely ignored by the API layer.
Fixed across three files (see below). Now all extra angles are
saved to disk and returned correctly.

## How multi-photo now works

**Adding an item:**
- Up to 5 photos via the strip on the Add page.
- First photo → `cover_photo_path` + `thumb_path` on server.
- Photos 2–5 → `extra_photos` (JSON array of paths) on server.

**Editing an item:**
- Remove a photo: × button updates `photos` array client-side, then
  `extra_photos_data` is sent to server with the new set. Old files
  deleted from disk automatically.
- Add another angle: Choose file → new Blob appended to `photos` →
  serialized as base64 in `extra_photos_data` → saved to disk.
- Remove cover and replace: null cover + new Blob → server clears
  old cover file and saves the new one.
