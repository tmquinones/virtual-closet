## Gotchas encountered today (so we don't re-step)

These are all already-debugged but worth keeping handy.

### 1. The Edit/Write tool byte-padding footgun (re-confirmed)
The Edit and Write tools intermittently produce output the same byte
length as the previous file content — padding with NULs or truncating
mid-line. Bit us THREE times today (`package.json`, `config.js`,
`email.js` after the SendGrid → Resend swap). Each was caught by
running `node --check` immediately after the edit.

**Fix:** for non-trivial edits, write via bash heredoc instead:
```bash
cat > "/path/to/file" << 'EOF'
...content...
EOF
```
The heredoc bypasses whatever the file tool is doing wrong.

### 2. Synology DSM doesn't ship `nano`
DSM has `vi` but no `nano`. Don't suggest `sudo nano /path/...` —
either use `vi` (intimidating but universal) or `cat > /path/... <<EOF`
heredoc, or SCP a file from the PC.

### 3. Newer Windows OpenSSH `scp` defaults to SFTP protocol
DSM's OpenSSH server uses legacy SCP. Result: plain `scp file user@host:path`
errors with `subsystem request failed on channel 0` or "initial request
failed." **Fix: always use `scp -O`** (legacy SCP mode) on Windows when
talking to a Synology box. Once on the NAS, plain `scp` is fine.

### 4. Multi-line paste + bash `read` builtin = data corruption
If a multi-line block contains a `read VAR` and the user pastes the
whole block including the data the read should consume, `read` consumes
the next line of the paste (which might be `echo "$VAR" | sudo tee...`)
instead of waiting for keyboard input.

**Fix:** for sensitive single-value entry, never embed `read` in a
multi-line paste block. Either:
- Split into two sequential commands so the user runs one at a time, OR
- Use `read -s -p "Prompt: " VAR` as a SINGLE line, then have the user
  paste the value, OR (most reliable for this user)
- SCP a file with the value from PC to NAS, then `cp` it into place.

### 5. Cloudflare Zero Trust UI was reorganized
"Public Hostnames" was renamed to **"Published application routes"**.
There's also a new sibling tab "Hostname routes (Beta)" which is for
WARP/private-network access (CGNAT) — DO NOT use that one for serving
HTTP to the open internet. Easy to confuse.

### 6. Terminal paste shortcuts vary by Windows terminal
- Modern Windows Terminal: Ctrl+Shift+V
- Classic PowerShell: right-click on title bar → Edit → Paste
- Universal: Shift+Insert
The user's terminal didn't accept right-click paste; Shift+Insert
worked but the SCP-from-Notepad workflow is now the recommended path
for any sensitive value.

### 7. Wrong-window mistakes
The user has both a PowerShell window (`PS C:\Users\admin>`) and an
SSH window (`tq_admin@home-nas:~$`). Several commands got run in the
wrong one. Future instructions should explicitly call out which window
each command belongs in.
