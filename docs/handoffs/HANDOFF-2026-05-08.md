## Day 3 plan (resume here once email is picked)

These are roughly 25 minutes of clicks + one SSH session. Order matters
where noted; rest is parallel-able.

### A. Email provider setup (~10 min)

1. Sign up at the chosen provider (free tier, no credit card).
2. Domain sender verification — provider gives you 3 CNAME records.
   Add them in **Cloudflare → DNS panel for tmfcloset.com**, with the
   orange-cloud proxy toggle **OFF** for those three records.
   (Reason: sender verification CNAMEs must resolve to the email
   provider's actual hostnames, not Cloudflare's proxy.)
3. Click "Verify" in the provider dashboard. Cloudflare DNS propagates
   in seconds; verification should succeed immediately.
4. Generate an API key (scope: "send only" / "transactional only").
   Save the key — you'll paste it into the NAS in step C.

### B. Code swap from SendGrid → chosen provider (~3-5 min, my job)

Edit `server/src/email.js`:
- For Resend: replace `@sendgrid/mail` import with `resend`. Change the
  `sgMail.send(msg)` call to `resend.emails.send({ from, to, subject,
  html, text })`. Update `package.json` dep name.
- For Brevo / Mailjet / MailerSend: similar — replace SDK + send call.
- For Gmail SMTP: switch to `nodemailer`, point at smtp.gmail.com:465,
  use her gmail + an app password (which she has to generate at
  myaccount.google.com → Security → App passwords).

Run `node --check src/email.js` and confirm.

### C. NAS prep (~10 min, Tiffany's job)

> Default plan: SSH from PowerShell. If SSH isn't enabled in DSM yet,
> Control Panel → Terminal & SNMP → check **Enable SSH service**.
> If she'd rather avoid SSH, every step also has a DSM web-UI
> equivalent (File Station + Container Manager + Text Editor), just
> slower.

```bash
# SSH in (replace 192.168.x.x with NAS IP from DSM → Control Panel → Network)
ssh tiffany@192.168.x.x

# Prepare directories
sudo mkdir -p /volume1/docker/tmfcloset/{db,photos,secrets}
sudo chown -R $(id -u):$(id -g) /volume1/docker/tmfcloset

# Generate JWT signing secret
openssl rand -hex 64 > /volume1/docker/tmfcloset/secrets/jwt.secret
chmod 600 /volume1/docker/tmfcloset/secrets/jwt.secret

# Save the email provider's API key
echo "<paste-the-api-key-here>" > /volume1/docker/tmfcloset/secrets/email.key
chmod 600 /volume1/docker/tmfcloset/secrets/email.key
```

Then copy the `server/` folder from her PC to
`/volume1/docker/tmfcloset/server/` — easiest via Synology Drive
Desktop (drag the folder), or `scp -r server/ tiffany@192.168.x.x:/volume1/docker/tmfcloset/`.

### D. Build + run the container (~3 min, Tiffany's job)

```bash
cd /volume1/docker/tmfcloset/server
docker compose build      # first build is 2-3 min (npm install + native compile)
docker compose up -d
docker compose logs -f    # watch for "[tmfcloset-api] listening on :8787"
# Ctrl+C to stop tailing logs (container keeps running)
```

If `docker compose build` fails, most likely cause is the native
compile step for `better-sqlite3` or `bcrypt`. The Dockerfile has the
needed Alpine deps (python3, make, g++). If it still fails, paste the
error to me.

### E. Cloudflare Tunnel — public hostname (~3 min)

In **Cloudflare → Zero Trust → Networks → Tunnels**, find the existing
tunnel pointed at the NAS (status HEALTHY).

- **Configure → Public Hostnames → Add a public hostname**
- Subdomain: `api`
- Domain: `tmfcloset.com`
- Service type: `HTTP`
- URL: `127.0.0.1:8787`
- Save.

Cloudflare auto-creates the DNS record. Within 30 seconds:

```bash
# from anywhere on the internet
curl https://api.tmfcloset.com/api/health
# expect: { "ok": true, "service": "tmfcloset-api", "time": "...", "migrations": ["001_initial.sql"] }
```

If this returns an error, common causes:
- 502 Bad Gateway → container isn't running, check `docker compose logs`.
- 530 Cloudflare error → tunnel + hostname config mismatch.
- Connection timeout → tunnel daemon not running on the NAS.

### F. Frontend CORS smoke test (~1 min)

In your browser DevTools while on https://tmfcloset.com:

```js
fetch('https://api.tmfcloset.com/api/health').then(r => r.json()).then(console.log)
```

Should print the same JSON. If you see "blocked by CORS policy",
double-check the `CORS_ORIGINS` env var in `docker-compose.yml`
includes `https://tmfcloset.com`.

   `/api/auth/*` (signup, login, refresh, logout, forgot-password,
   reset-password) and store JWTs in memory + refresh token in
   localStorage. Rewrite `js/db-r3.js` from an IndexedDB wrapper into
   an API client.
4. **One-time "migrate to cloud" button.** Lives on a new page or in
   the drawer footer. Runs `dbExportAll` against the user's local
   IndexedDB, POSTs the envelope to `/api/migrate`. On success,
   re-points the frontend at the API and clears local IndexedDB.

This is also when the **Insights tabs empty-state confusion** will

## Stranded data (the tiffany account)

Tiffany's real closet data lives in IndexedDB at origin
`tmquinones.github.io` (the original GitHub Pages URL). The custom
domain `tmfcloset.com` set on this repo causes GitHub Pages to send a
**301 redirect** from `tmquinones.github.io/virtual-closet/` →
`tmfcloset.com`. The redirect fires before the page can load and
reach the old IndexedDB.

The data isn't lost. It's reachable from any non-redirected path on
`tmquinones.github.io` (IndexedDB is keyed by origin, not path), but
the easiest extraction once the backend is live is:

1. Temporarily remove the CNAME file from `hugo-site/` and push.
2. Wait ~30 sec for GitHub Pages to redeploy without the redirect.
3. Visit `https://tmquinones.github.io/virtual-closet/` — direct.
4. Sign in as `tiffany` (the account exists at that origin).
5. Click `≡` → **Export Backup**. Save the JSON.
6. Restore the CNAME file, push, wait.
7. Visit `https://tmfcloset.com`, sign up for the cloud account.
8. Use the new "Migrate to cloud" button (Days 4-5) which POSTs the
   JSON to `/api/migrate`.

Or do steps 1-5, then 7-8 directly without restoring the CNAME first
— functionally equivalent. Either way the cloud import lands the data
on the NAS and it stops being origin-locked forever.

## Critical gotchas (read before editing)

### Edit-tool truncation footgun

Documented at length in HANDOFF-v51.md. **Did not bite this session**
— every server-side file was written via the Write tool from scratch
and `node --check` passed on the first attempt for all 9 JS files.
Pattern is: after any non-trivial Edit on `js/*.js`, always run
`node --check <file>` before bundling. If it fails with "Unexpected
end of input," the tail was dropped — recover via `head -n` + heredoc
append, or extract the original from `dist/app.bundle.js` (every
source is embedded between `/* ===== js/<filename> ===== */` markers).

### npm install hasn't run yet

The deps in `server/package.json` are not installed locally. They'll
be installed during `docker compose build` on Day 3. If you want to
run the server outside Docker for local dev, `cd server && npm install`
first — better-sqlite3 and bcrypt require a C compiler.

### CORS allowlist

`docker-compose.yml` sets `CORS_ORIGINS=https://tmfcloset.com,https://tmquinones.github.io`.
The github.io entry is intentional — needed during the transition
when Tiffany visits the old origin to extract her stranded closet
data. Drop it once data has fully migrated to the cloud.

### Photo storage

Photos go on the NAS filesystem at
`/volume1/docker/tmfcloset/photos/<user_id>/<kind>/<uuid>.<ext>`,
not in the SQLite DB. The DB stores the relative path. Express
serves them with auth checked per request (Days 4-5 work).

### Edit `email.js` BEFORE the docker build

The current `email.js` lazy-imports `@sendgrid/mail`. If we switch to
Resend tomorrow, the dep needs to change in `package.json` too —
otherwise `npm install` will pull SendGrid (harmless but wasteful)
and the lazy require will fail at first email send.
