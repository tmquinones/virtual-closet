### 2. Bug fix: `_rowToItem` extra_photos (db-r4.js) — shipped in v63

The server returns `extra_photos` as an already-parsed JS array. `_rowToItem` was
calling `JSON.parse()` on it again, which silently failed (arrays coerce to a comma-
joined string that is invalid JSON). Galleries therefore showed zero extra photos.

**Fix:** check `Array.isArray(row.extra_photos)` instead of JSON-parsing.

```js
// Before (broken)
const paths = JSON.parse(row.extra_photos);  // always threw → []

// After (fixed)
const paths = Array.isArray(row.extra_photos) ? row.extra_photos : [];
return paths.filter(Boolean).map(p => API_PHOTO_BASE + p);
```

### 3. Bug fix: `naturalDimensions()` with URL strings — shipped in v64

`insights-r7.js`, `audit-r1.js`, and `style-dna-r1.js` all called
`URL.createObjectURL(blob)` where `blob` is now a URL string (in the API version, photos
are served as URLs, not Blobs). `createObjectURL` throws on non-Blob inputs, causing:

- Insights → Photos tab: stuck at "Scanning photos…" forever
- Insights → Declutter/Gaps/Colors tabs: unreachable (view blocked)
- Photo Audit route: same hang
- Style DNA color analysis: same crash

**Fix in all three files:** guard with `instanceof Blob` check.

```js
// Before
const url = URL.createObjectURL(blob);

// After
const isBlob = blobOrUrl instanceof Blob;
const url = isBlob ? URL.createObjectURL(blobOrUrl) : String(blobOrUrl);
```

`style-dna-r1.js` also got `img.crossOrigin = 'anonymous'` for canvas cross-origin
reads when loading remote API photo URLs.
