## Critical gotchas (carry forward)

### Bundle drops — verify SOURCES list every build

**v52 dropped `drawer-r1.js` + `scheme-r1.js` from the SOURCES list
silently.** v53 then dropped them again. v54 restored. Always verify
after building:

```bash
head -3 dist/app.bundle.js | sed -n '2p' | grep -oE "js/[a-z0-9_-]*\.js" | wc -l
```

44 sources as of v54. If the count drops without an explanation, a
file got cut.

### `scp -O` is non-negotiable

Windows OpenSSH defaults to SFTP, which Synology DSM doesn't support.
Always `scp -O` from PowerShell to NAS.

### PowerShell vs DevTools vs SSH

Three windows, three syntaxes. Easy to confuse:

- **PowerShell** — `curl`, `git`, `scp`, `cd`, `dir`
- **SSH (NAS)** — `sudo docker compose ...`, `cat`, `vi`
- **DevTools Console** — `document.querySelector(...)`, anything JS

If a JS-looking command errors with "not recognized as a cmdlet,"
it was pasted in the wrong window.

### Service-worker cache lag

After every ship Tiffany has to: DevTools → Application → Service
Workers → Unregister → Storage → Clear site data → reload → sign in
again. The cloud auth means signing in is just typing
username+password; no data is at risk since IndexedDB on the origin
is no longer the source of truth.

### Custom-domain on/off cycle requires re-verification

Removing the custom domain from repo Pages settings, then re-adding
it, triggers user-level verified-domains TXT-record check IF that
feature is enabled on the account (Tiffany's is). The TXT record
challenge is stable — same hostname (`_github-pages-challenge-tmquinones`)
and a fresh value each time. Cloudflare DNS propagates instantly.

### CNAME-flip data recovery pattern (preserved for future)

If we ever need to extract IndexedDB data from `tmquinones.github.io`
again, the recipe is in `RECOVERY-SNIPPET.md`. Two-step DevTools
console snippet, runs in a normal browser tab (NOT incognito — separate
storage) with DevTools "Disable cache" enabled. Disable the custom
domain first to avoid the 301 redirect.
